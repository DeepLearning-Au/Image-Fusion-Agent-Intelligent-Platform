# 第 7 课：知识库版本与原子发布

## 1. 为什么不能直接覆盖

解析、分块或Embedding任一步失败时，直接覆盖会让线上知识库处于不完整状态。
因此正式更新必须先构建独立 generation。

## 2. 状态机

```text
building → ready → active → retired
    └────────→ failed
```

- `building`：解析文档、生成父子块和向量；
- `ready`：数量、一致性和向量完整性校验通过；
- `active`：线上检索唯一可见的版本；
- `retired`：历史版本，可用于回滚；
- `failed`：构建失败，不影响 active 版本。

## 3. 原子发布

发布操作在一个数据库事务中完成：

```text
旧 active → retired
新 ready  → active
提交事务
```

中途发生异常时事务整体回滚，旧 active 仍然生效。

## 4. 管理接口

- 查看版本：`GET /api/rag/generations`；
- 构建版本：`POST /api/rag/generations/build`；
- 发布草稿：`POST /api/rag/generations/{id}/publish`；
- 回滚历史版本：`POST /api/rag/generations/{id}/rollback`。
