# 第 2 课：结构化产品数据库

> 本课记录第一阶段的人工种子导入；PDF自动候选、审核和发布见《05_产品参数审核与发布》。

## 本课目标

让系统同时拥有两种互补的数据能力：

- 文档 RAG：保存原文上下文，适合解释特点、场景和局限；
- 结构化产品库：保存型号、分辨率、帧率、协议和价格状态，适合精确过滤与比较。

本课第一阶段只导入 IPT640M，用一个产品验证完整链路，再扩展到另外两类设备。

## 为什么不能只把 PDF 切块

假设用户提出：“找一款红外分辨率至少 640×512、帧率至少 25Hz，并支持 SDK 的设备。”

纯文本检索只能寻找相似文字，不能稳定执行三个数值条件。结构化数据库可以直接比较：

- `resolution_width >= 640`；
- `resolution_height >= 512`；
- `stream_frame_rate >= 25`；
- `sdk_api_support = true`。

因此企业级选型通常是“数据库先执行硬条件过滤，RAG 再解释软条件”。

## 表为什么要拆开

### manufacturers

厂商信息只保存一份。多个产品引用同一个厂商，避免名称和官网重复。

### products

保存稳定的产品主数据：型号、名称、模态、简介和生命周期状态。

### spec_definitions 与 product_spec_values

前者定义“分辨率宽度是什么类型、默认单位是什么”，后者保存某款产品的实际值。数值、布尔、文本和数组分开存储，才能正确比较。

例如数字 `640` 不能只保存成字符串 `"640px"`，否则数据库可能把 `1024` 错误地排在 `640` 前面。

### source_references

保存来源文档、SHA-256、页码和官方下载地址。产品事实即使进入数据库，也必须可以回到原始 PDF 验证。

### product_prices

价格不是产品的固定属性。它有公开价、经销商参考价、历史价、询价、币种、税费和有效期，所以必须单独建表。

IPT640M 当前写入的是 `inquiry`，金额保持 `NULL`，表示官方资料没有提供公开价格。

### product_media

保存产品图片或官方资料页的位置，同时关联来源页，避免把不明图片当作官方产品图。

### product_scenarios

保存厂商明确说明的适用场景，并区分支持、条件支持和不建议。

### fusion_compatibility

这是本项目独有的业务表，用于判断产品能否作为 MambaDFuse 输入源，包括：

- 可以提供红外流还是可见光流；
- 是否能取得独立模态；
- 是否支持硬触发和时间同步；
- 是否有 SDK；
- 是否提供标定数据；
- 是否仍需配准。

## 为什么字段允许 NULL

`false` 表示资料明确说明“不支持”，`NULL` 表示资料没有说明。两者不能混淆。

例如 IPT640M 资料没有说明与外部可见光相机的硬件同步能力，因此 `hardware_trigger` 和 `timestamp_sync` 写为 `NULL`。Agent 应回答“需要向厂商确认”，而不是回答“不支持”。

## 为什么现在仍使用 SQLite

这一阶段要学习的是关系建模、约束、事务、幂等导入和来源追踪。如果同时引入 PostgreSQL、容器和网络配置，出现问题时不容易判断是数据模型还是环境问题。

当前代码通过 Repository 隔离数据库访问，并使用显式 schema migration。完成三类产品建模和查询验证后，再迁移到 PostgreSQL + pgvector；届时上层 Agent 和 API 不需要重写业务逻辑。

## 企业级设计点

- `CHECK` 约束限制模态、价格类型和状态取值；
- 外键保证产品、参数、媒体和来源之间不出现孤儿数据；
- 整个产品种子在一个事务内导入，失败时不会留下半个产品；
- 同一个种子重复导入不会创建重复产品；
- PDF 使用 SHA-256 标识，文件改变后可以识别新版本；
- 产品导入采用完整快照，已删除字段不会残留；
- Repository 接受测试数据库路径，不依赖正式数据库才能测试。

## 本阶段接口

- `GET /api/products/status`：结构化目录统计；
- `GET /api/products`：产品列表；
- `GET /api/products/{model}`：产品完整信息和来源；
- `GET /api/products/search`：按模态、分辨率、帧率和 SDK 精确过滤。

示例过滤条件：

```text
/api/products/search?modality=pure_infrared&min_width=640&min_height=512&min_fps=25&sdk_required=true
```

## 当前阶段边界

- 只导入 IPT640M；
- 官方 PDF 第 1 页被渲染为带来源的产品资料图；
- 暂不让 Agent 自动调用结构化过滤接口；
- 暂不导入可见光和双模态产品；
- 暂不迁移 PostgreSQL。

这样可以先证明数据库设计正确，再扩大范围。

## 2026-08-27 实际验收结果

- 结构化产品：1；
- 厂商：1；
- 类型化参数：20；
- 价格状态记录：1；
- 官方资料图片：1；
- 数据库迁移版本：1。

重复导入两次后，产品数仍为 1，说明导入是幂等的。以下条件可以稳定返回 IPT640M：

```text
modality = pure_infrared
resolution_width >= 640
resolution_height >= 512
stream_frame_rate >= 25
sdk_api_support = true
```

把最小宽度改为 1024 后返回空列表，证明系统执行的是数值过滤，而不是模糊匹配产品介绍。

本地接口、产品详情、产品筛选、产品卡片和官方资料图片均通过测试，页面控制台没有错误。
