# 第 6 课：查询理解与混合检索

## 1. 查询理解

系统从用户问题中提取：

- 设备模态和型号；
- 最低分辨率、帧率；
- ONVIF、RTSP、MQTT、USB3 Vision等协议；
- SDK、防护等级和融合要求；
- 最低价、最高预算、币种以及价格是否为硬条件；
- USB、GigE Vision、Camera Link、CoaXPress、MIPI、HDMI、RJ45、PoE等接口；
- 使用场景。

硬条件使用确定性规则提取，避免大模型把数字和单位改错。

### 1.1 查询容错与置信度分层

确定性规则前增加领域查询归一化，统一全角字符和空白。协议名称只在有限白名单内
做模糊纠错，例如把 `USB3 Vison` 识别为 `USB3 Vision`，并在结果中保留原词、
纠正词、置信度和应用方式，避免静默改写用户需求。

- 高置信度协议纠错：可以进入硬过滤，同时向用户展示纠错结果；
- 中等置信度协议：不进入硬过滤，要求用户确认；
- 型号：即使只差一个字符也只提供候选建议，不自动替换；
- 异常分辨率和非法 IP 等级：不进入硬过滤，标记为待确认。

API 会返回 `query_diagnostics`，包括纠错记录、每项约束的置信度、歧义条件和
`needs_confirmation`。这让查询理解从黑盒解析变为可观察的决策步骤。

当全部硬条件导致零结果时，系统每次只移除一组条件进行探测，并返回
`relaxation_suggestions`。例如说明“若放宽最低分辨率，可找到哪些型号”，但不会
自动修改用户要求。

## 2. 混合检索

```text
用户问题
  ├─ MySQL：排除不满足硬条件的产品
  └─ 产品关联RAG
      ├─ FTS5 + BM25：倒排召回并按词频、逆文档频率和长度归一化排序
      │    └─ LIKE：FTS5不可用或两字短中文查询未命中时降级
      └─ Embedding：召回表达不同但语义相近的文本块
               ↓
             RRF 融合
               ↓
        文档BGE Reranker 精排
               ↓
        证据按型号/产品文档回挂
               ↓
       产品偏好排名 + 证据排名
               ↓
          产品级RRF融合
               ↓
       BGE读取完整产品卡片重排
               ↓
      Top-5产品和证据交给大模型
```

SQL决定产品是否满足硬条件，任何语义得分都不能让不合格产品重新进入候选集。
RAG负责判断合格产品和用户场景的相关性。向量直接绑定 SQLite
中的 `chunk_id`，保证文档、文本块和向量可以同步删除、增量更新。

明确的“不超过、至少、以内”预算进入MySQL硬筛选；“大约、左右、优先”只参与
偏好排序。没有公开价格的产品不会伪造价格，硬预算查询会返回无匹配并提示询价数据缺失。

## 3. 使用位置

- Agent选型工具：`product_advice_tool`
- API：`POST /api/products/hybrid-search`
- 向量索引：`POST /api/rag/vector/rebuild`

示例请求：

```json
{
  "query": "推荐双模态、IP66、支持MQTT和SDK的室外设备",
  "top_k": 5
}
```

## 4. 回答边界

同步、时间戳和标定资料缺失时，系统会列为“待厂商确认”，不会推断为支持。

## 5. 为什么使用 RRF

关键词分数和余弦相似度不在同一量纲，直接相加不稳定。RRF只使用两路结果的
排名进行融合，既保留精确型号命中，也能补充语义相近内容。

## 6. BGE Reranker

RRF负责合并两路排名，BGE Reranker负责逐条判断“问题和候选文本是否真正相关”。
系统默认重排前20条候选，再把前5条交给大模型。

- 默认模型：`BAAI/bge-reranker-base`；
- 模型只加载一次，并按批次推理；
- 未下载或运行失败时自动保留RRF结果；
- 管理接口：`GET /api/rag/reranker/status`；
- 预加载接口：`POST /api/rag/reranker/preload`。

## 7. 补充文档入库

`data/md/knowledge_docs` 被配置为补充知识目录。系统按文件哈希增量导入：

- 新文件：创建文档、文本块和向量；
- 未修改文件：直接跳过；
- 已修改文件：替换对应文档，并重新生成其向量；
- 接口：`POST /api/rag/import-supplemental`。

## 8. 父子块分层

入库时先按一级、二级标题或PDF页边界生成父块，再在父块内部生成子块：

```text
子块召回 → RRF融合 → BGE重排 → parent_id回表 → 完整父块 → 大模型
```

- 父块上限：约2000字符，只负责提供完整章节；
- 子块上限：约500字符，重叠80字符，只对子块生成向量；
- 多个命中子块属于同一父块时，父块只返回一次；
- 重建接口：`POST /api/rag/rechunk`。

## 9. 标准 BM25

SQLite FTS5 使用原生 `bm25()` 排序，列权重为标题 8、类别 4、正文 1。
FTS 索引使用 trigram 分词以适配连续中文；原生 BM25 分数越小（越负）代表
相关性越高，系统仅做单调归一化用于展示，不改变 BM25 排名。

每条关键词结果都会携带：

- `sparse_retriever=fts5_bm25`；
- `bm25_raw_score` 原始分数；
- `final_score` 归一化展示分数。
